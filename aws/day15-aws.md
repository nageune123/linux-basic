# AWS Day15 — S3 + IAM Role

## 목표
EC2에서 액세스 키를 직접 입력하지 않고 IAM Role로 비공개 S3 파일 읽기.

## 실습
1. 퍼블릭 액세스를 차단한 S3 버킷 생성 및 테스트 파일 업로드
2. 해당 버킷만 읽을 수 있는 IAM 정책 생성
   - s3:ListBucket: 파일 목록 조회
   - s3:GetObject: 파일 읽기
3. EC2용 IAM Role 생성 → 정책 연결 → Public EC2에 역할 연결
4. SSH 접속 후 AWS CLI 설치
5. 역할 인증 및 S3 접근 테스트

## 검증 결과
| 작업 | 결과 |
|---|---|
| sts get-caller-identity로 역할 확인 | 성공 |
| aws s3 ls로 파일 목록 조회 | 성공 |
| aws s3 cp로 파일 내용 출력 | 성공 |
| S3 업로드(PutObject) 시도 | AccessDenied — 의도한 거부 |

## 핵심 개념
- S3: 파일을 객체로 저장하는 AWS 저장소
- 정책: 어떤 대상에 어떤 작업을 허용할지 정하는 규칙
- 역할: EC2가 임시 인증 정보를 받아 AWS 권한을 사용하도록 하는 신분
- 최소 권한: 필요한 읽기만 허용하고 쓰기는 허용하지 않음

## 문제 해결
- SSH 키 파일을 찾지 못함 → 키 파일의 전체 경로를 지정해 해결
- apt로 awscli 설치 실패 → AWS 공식 ZIP 설치 파일로 설치

## 배운 점
명령어는 작업을 요청하고, IAM 정책은 그 요청의 허용 여부를 결정한다.
